3.3V TTL Levels

PC USB-to-UART (Adapter) ─── CONNECT ───▶ PIC32CXMTC Header Pin

Adapter TXD (Orange / Green) ──────► Pin 6 (DLMS_URX)
Adapter GND (Black) ◄─────► MCU GND (Common Ground)
⚠️ IMPORTANT: Ensure your USB-UART dongle is set to 3.3V I/O logic level. Connecting a 5V TTL adapter directly without level-shifting will damage the PIC32CXMTC GPIOs!
⚙️ Firmware Verification Status
Ready to Run

The firmware running in your PIC32CXMTC includes the complete driver pipeline:

  • FLEXCOM1 Initialization: Configured automatically in SYS_Initialize() at 9600 bps 8-N-1.
  • Interrupt Handler: Registered via FLEXCOM1_USART_ReadCallbackRegister() with a 2048-byte lock-free circular buffer.
  • Periodic Task: Polled continuously via APP_DLMS_Tasks() in SYS_Tasks().
  • Live Metrology: Registered adapter dynamically queries APP_METROLOGY_GetMeasure() and APP_ENERGY_GetCurrentEnergy().
Diagnostic Counters: You can read app_dlmsData.rx_bytes, tx_bytes, and rx_errors in the MPLAB X watch window at any time to monitor hardware traffic!

Handling "GetObjects Failed" (Expected Behavior)

Right after connecting, GXDLMSDirector may display a notification:

GetObjects Failed. Access Error: Device reports a undefined object

This is completely normal and expected. In DLMS, GetObjects is an optional feature where the client requests the dynamic Association View table (object_list) to auto-populate the GUI tree. Lightweight embedded firmware omits this dynamic table to save Flash and RAM. Your connection is alive and working properly!

4

Add COSEM Objects Manually (Edit ➔ Add Object)

Because the "Generic" device profile starts with an empty tree, add the objects you want to read:

  1. Click on your device name (e.g. Generic) in the left tree so it is highlighted.
  2. Go to the top menu bar and click Edit ➔ Add object... (or right-click device ➔ Add object...).
  3. In the dialog, configure your first object:
    • Object type: Select Data (Class ID 1)
    • Logical Name: Enter 0.0.96.1.0.255 (Meter Serial Number)
  4. Click OK. A folder named Data appears with 0.0.96.1.0.255 inside.
  5. Repeat for Voltage Phase A:
    • Object type: Select Register (Class ID 3)
    • Logical Name: Enter 1.0.32.7.0.255 (Voltage Phase A RMS)
5

Read Serial Number and Live Metrology

In the left tree, right-click any added object and select Read:

  • Right-click Data ➔ 0.0.96.1.0.255 and click Read $\rightarrow$ Value displays PIC32CX00001.
  • Right-click Register ➔ 1.0.32.7.0.255 and click Read $\rightarrow$ Value displays live ADC voltage (e.g. 230.2 V).
💡 Pro Tip: Click File ➔ Save in GXDLMSDirector to save your project as PIC32CXMTC.gxc. Next time you open this file, all your objects will already be in the tree ready to read without needing to re-add them!

Handshake Mechanism: When you click Connect in Suite 0 mode:
  1. SNRM ➔ UA: HDLC Data Link layer establishes connection.
  2. AARQ ➔ AARE: Client sends 16-byte random challenge $CtoS$. Meter generates 16-byte random challenge $StoC$ and responds.
  3. HLS 5 ACTION.req: Client executes reply_to_HLS_authentication with $f(StoC)$ computed via AES-GMAC. Meter verifies tag.
  4. HLS 5 ACTION.resp: Meter sends mutual authentication tag $f(CtoS)$ back to client.
  5. Mutual Association Established: All subsequent GET/SET requests are encrypted with AES-GCM (Security Control byte 0x30).

🛠️ Diagnostic & Troubleshooting Matrix
Self-Healing Guide
!

Problem: GXDLMSDirector times out; no reply to SNRM

Root Causes & Solutions:

  • TX/RX Swapped: Pin 5 is DLMS_UTX (connect to PC RX) and Pin 6 is DLMS_URX (connect to PC TX). If swapped, the MCU will never see bytes.
  • Missing Common Ground: The USB-to-UART GND pin must be connected to the PIC32CXMTC board GND.
  • Wrong COM Port: Verify in Windows Device Manager which COM port corresponds to your USB-UART adapter.
  • Baud Rate Mismatch: Must be 9600 bps, 8 bits, No parity, 1 stop bit (8-N-1).
!

Problem: Connection drops during Suite 0 Handshake (HLS 5 Authentication Error)

Root Causes & Solutions:

  • Mismatched System Titles: Server System Title must be 4D 43 48 00 00 00 01 01. If the client sends an unknown System Title, GMAC verification will fail.
  • Mismatched Authentication Key: Must be D0 D1 D2 D3 D4 D5 D6 D7 D8 D9 DA DB DC DD DE DF.
  • Invocation Counter Replay: If you reset the meter, the meter's stored client Invocation Counter resets. In GXDLMSDirector, reset the Invocation Counter to 0 or restart GXDLMSDirector.
i

Problem: Metrology values read as 0.0 or simulated values

Root Causes & Solutions:

  • Metrology Engine Starting: The PIC32CXMTC Metrology core takes a few seconds after power-on to load the calibration parameters and DSP binary. During this window, the adapter returns default simulated benchmarks.
  • AC Voltage Signal: If AC mains voltage is not connected to the voltage divider inputs of the evaluation board, voltage and current registers will naturally read 0.0 V.
!

Problem: "GetObjects Failed. Access Error: Device reports a undefined object"

Root Causes & Solutions:

  • Expected Behavior for Public Client: The meter does not host the dynamic 700-byte object_list directory in Public mode to save Flash/RAM. The connection itself is fully active and healthy.
  • Solution: Simply use Edit ➔ Add object... in GXDLMSDirector to add the OBIS codes you need (e.g. Data ➔ 0.0.96.1.0.255), right-click and click Read.
  • Permanent Save: Save your configured meter as PIC32CXMTC.gxc via File ➔ Save to prevent GXDLMSDirector from prompting for GetObjects on subsequent launches.
!

Problem: MPLAB X Programming Error "[Pgm] at 0x1000000, expected 0x2007fff8, got 0x2007ffd8"

Root Causes & Solutions:

  • SWD Clock Speed Too Fast: High-speed clock signal integrity on ribbon cables/jumpers causes SWD verify bit glitches. In project Properties ➔ Tool ➔ Program Options, change Program Speed from Normal to Low (or reduce frequency to 1.0 MHz / 500 kHz).
  • Flash Erase Incomplete: Flash bits can only transition from 1 to 0 during writing; they cannot flip to 1 without a sector erase. Click the Erase Device Memory button in MPLAB X before programming.
  • USB Power Drop: Ensure the board is connected directly to a PC motherboard USB port (avoid unpowered hubs).
